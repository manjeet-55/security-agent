What happens inside a scan.

Every request passes one gate. Every finding points at something recorded. Nothing is guessed.

  1. Input

    project.yaml

    Your list of sites and servers. Nothing outside it is ever touched.

  2. Permission

    Your yes

    Stored outside the repo and tied to the addresses you listed, so a cloned repo cannot confirm itself.

  3. The only way out

    Scope gate

    Listed targets only. GET and HEAD. Redirects are not followed, cloud-metadata addresses are never probed.

    Refused: not on your list
  4. Fixed rules

    33 checks

    No AI model and no randomness. The same inputs give the same result.

  5. Proof

    Evidence

    Each finding cites what was observed. A check that could not run is unknown, not passed.

    Unverifiable
  6. Output

    Report

    Fix first, then PDF, HTML and Markdown. Stable ids let the next scan say what changed.

Code, websites and servers.

Thirty-three checks. Each has a plain-language reason and a fix written for your stack, and a severity you can read at a glance.

5

Your code

Needs nothing extra

  • HNo secrets in your source files
  • HNo secrets in the git history
  • HNo .env or key files committed to git
  • H.env and key files are in .gitignore
  • Hnpm dependencies have no known vulnerabilities

Stays on your machine. Only package names and versions go to public advisory databases.

17

Websites and APIs

Needs the address, and your OK

  • HSecrets, .git and source maps are not served
  • HTLS 1.0 and 1.1 are refused
  • HCertificate is trusted, with 21+ days left
  • HPlain HTTP redirects to HTTPS
  • HCORS does not expose responses to unknown sites
  • HDNS does not point at a name that no longer exists
  • MHSTS is on with at least 180 days
  • MContent-Security-Policy limits script sources
  • MCookies set Secure, HttpOnly and SameSite
  • and 8 more: other headers, cipher suites, header size

Read-only GET and HEAD requests. Redirects are never followed.

11

Servers

Needs you to run a read-only script

  • HDatabases do not listen on every interface
  • HAdmin and database ports are not reachable
  • HNo pending package security fixes
  • MSSH root login is disabled or key-only
  • MSSH password logins are disabled
  • MAutomatic security updates are on
  • Mnginx refuses SSLv3, TLS 1.0 and 1.1
  • MThird-party packages are known and patched
  • and 3 more: reboots, nginx version, load balancer

secagent never logs in. You bring the script’s output back.

H high · M medium · L low. Severity is set by the check, not by a model.

It only reads, and only what you list.

These rules are enforced in code and covered by tests. They are not settings.

Read-only

  • Only your list

    Sites and servers in project.yaml, nothing else. An address a page redirects to is refused too.

  • You say yes first

    Nothing on the network is touched until you confirm. Your yes is stored outside the project, not in the repo.

  • No logins, no guessing

    GET and HEAD requests, TLS handshakes and TCP checks. No form posts and no password attempts.

  • Evidence or nothing

    Every finding cites a recorded observation. A check that could not run is marked unverifiable, never passed.

  • Values never printed

    Output carries the file, the line, the pattern and a short fingerprint. The secret itself never leaves.

  • People decide risk

    An AI assistant cannot edit project.yaml, accept a risk or approve a lesson. Only you can.

Claude Code, Cursor or any MCP client can scan, explain and help fix. secagent still decides every status.

$ secagent mcp setup claude mcp add secagent -- \ secagent mcp --dir /path/to/project Ask: "Run a security review of this project"

Gate your pipeline

Run it in CI with no questions. The build fails when a finding reaches the severity you choose.

$ secagent scan --only code --fail-on high exit 1 on a high or critical finding no questions asked; for scripts and CI --only code, web or host picks a group
